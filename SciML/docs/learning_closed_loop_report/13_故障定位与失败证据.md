# 第 13 章：故障定位——不要把“跑不通”和“结果不好”混为一谈

## 13.1 先给失败分类，再决定改哪里

| 类别 | 例子 | 第一动作 |
|---|---|---|
| 环境/调用错误 | 找不到 SciML 包、模块路径写错 | 核对工作目录、解释器、真实模块位置 |
| 数据契约错误 | 非活动/活动 NaN 混淆、shape 错、源摘要变了 | 定位具体字段/工况/版本，停止该阶段 |
| 数值实现错误 | 近零残差误用 1 m 尺度制造假位移、数值导数误导优化 | 制造最小例子、检查量纲与梯度 |
| 评价实现错误 | 同工况泄漏、错误广播、混用测试群体 | 重建输入权限与独立指标计算 |
| 模型能力不足 | 材料 OOD 失败、三循环神经误差超过线性 | 保留负结果，分析分布与模型假设 |
| 证据不存在 | 工程安全阈值未知、实验数据缺失 | 明确未知项，不能用“检查无报错”代替证明 |

前四类可能需要修复代码；第五类不一定是软件 bug；第六类也不是把阈值写宽就能解决。
“一碰到失败就 blocked”和“所有失败都继续重复运行”都没有完成诊断。
本学习任务允许修复有证据的实现问题并验证，但不授权新增昂贵仿真去满足旧论文数量要求。

## 13.2 通用定位流程

1. 记录真实退出码、终态 JSON 和异常堆栈；一个工具等待返回不代表程序结束。
2. 找最早违背契约的地方，而不是只看最终指标。
3. 保存旧源码/参数摘要与旧结果，选一个新的诊断输出目录。
4. 缩小到能复现问题的字段、工况或几行数组，不先大幅改网络。
5. 提出可检验原因：如果原因正确，改动后哪个中间量应改变，哪些应不变？
6. 修改共享实现，增加能捕获原错误的测试；不要只针对一个测试工况调参数。
7. 先跑小测试，再运行新的完整相关阶段；独立重算指标，保留仍然不好的结果。

报告至少要写清“症状→证据→原因→修复→测试→适用边界”。只写“修好了”无法供你独立学习。

## 13.3 路径与 Python 包导入

症状：直接运行某个文件时出现 `No module named SciML`，或路径不存在。
原因可能是工作目录不在仓库根、解释器不同、执行文件路径与包导入方式混用。
先用真实文件清单找位置，再按 `python -m 包.模块` 调用；不要复制文件到临时目录碰运气。

本报告的主动学习/设计模块位于 `SciML/active_learning`。误认为它们在 `models/v12` 会得到不存在路径。
在 PowerShell 原生命令参数里，`rg 路径/08*` 未必按你想的方式展开；可用
`rg ... 目录 -g '08*'` 的文件过滤语法或直接给准确文件名。一次查找返回无匹配不等于任务无法继续。

环境迁移后的原始来源绝对路径失效，也不是数据“可以安全忽略”；若需要完整审计，必须恢复可追溯位置映射。

## 13.4 初态偷偷用了未来数据

旧 canonical 状态构造会从阶段 4 的真实 HTF 首帧填入整个循环起点。
这些值与请求温度差看起来很小，但实际推理时尚不可知，所以是信息权限错误。
已执行的检查发现全部 63 例有该问题，最大初态差约 0.0165883 K。

仅把旧模型的测试输入改成请求初态，旧模型阶段 1 SMA 测试 RMSE 从约 0.108866 K 变成 3.253811 K。
这说明旧模型适应了旧输入契约，不能据此认为真实请求初态“不准确”。
正确修复是明确初始化来源、构造新的复合边界目标并重新训练，同时保留旧模型作为失败诊断证据。

新自主函数只接收请求/允许初态，不接收未来目标记录；测试还注入无效未来负载，确认推理不依赖它。
这种权限检查比单纯在特征名里搜索 “future” 更强。

## 13.5 接近零的残差尺度，为什么会制造巨大位移

Ridge 已几乎完全拟合某些受边界约束的位移通道，其残差均方根接近零。
旧代码给这些通道用 1 的备用尺度，看起来是避免除零；但状态单位是米，1 就是 1 m。
神经网络极小的无量纲输出乘上 1 m，会变成明显假位移。

诊断必须同时看“归一化残差多大”和“反变换后单位是什么”。
本项目修复为小于数值阈值的残差通道关闭神经修正，并显式约束 u 中心等边界。
原失败实现与结果保存在 wp3-boundary-r1 和 source_snapshots，新结果为 wp3-boundary-r2。

不要把这个修复误读成所有小尺度都该裁掉：阈值与当前单位有关，改变单位系统时必须重新检查。
也不要为了让位移好看而把全部输出剪到真值范围；那会掩盖模型失效。

## 13.6 51 点镜像丢掉的不是几个插值点，而是信息

症状：阶段 4 用径向状态构造入口后，温度场串接误差显著增大。
原因：径向 51 点只能描述对称部分，方向性换热后的奇分量不在其中。
`Tstrip=mirror(Tradial)+odd(Tstrip)` 中 odd 部分有 50 个独立自由度，不能凭镜像恢复。

当前 63 例的对应入口关系已回查，纯镜像差异可达约 3.35585 K。
新串接使用模型自己预测的阶段 2 末态奇分量，不使用真实未来阶段 4 条带。
S4 SMA/HTF RMSE 从约 1.696596/1.359016 K 降到 0.592715/0.610452 K。
这证明该输入修复对当前实验有帮助，不证明完整能量或任意多循环都闭合。

## 13.7 浮点差异为什么不能按物理门禁处理

记忆串接首次验证遇到跨批处理的逐位不等，最大差约 5.684×10⁻¹⁴ K。
同一个线性代数运算改变 batch 形状，可能改变求和顺序；这与 0.1 K 的物理误差不是一回事。

修复保留原分批方式的精确重放检查；仅跨批比较采用与机器 epsilon 和数值幅度成比例的界限。
旧失败源码/证据保存，没有把数据集物理阈值改宽。
判断顺序是：确定模型、输入、权重相同→确认差异来源与量级→限定数值比较范围。
不能看到任何差异就统一设 `atol=1`，也不能把一切不等都当成科学失败。

## 13.8 优化器说 success，但参数并不是最优

局部热节点反演的旧经典对照把自适应 ODE 求解嵌入有限差分优化。
求解误差扰动了数值梯度，优化器在约 0.5 的初值附近报告收敛；目标扫描却显示约 1.25 更好。
这不是证明 PINN 优于经典优化，而是经典对照实现有问题。

修复保持同一个分段线性流体温度 forcing，改用该 forcing 下的精确递推。
对小 rate×dt 使用 expm1 和展开式避免相减消去，再用独立高精度积分核验。
修复后的经典与神经有效速率相近；旧结果、六个神经权重以及修复前后差异都保留。

可迁移的排错方法：优化状态成功只是停止条件满足。应检查目标曲线、梯度、不同已知测试参数，
以及理论可辨识性。若观测本来不含参数信息，再精确的优化也不能创造信息。

## 13.9 材料 OOD 失败：为什么不能继续调直到分数好看

只用 recA 训练时，材料 one-hot 标准化后的对应列恒为零。
首层这些输入列对数据损失的梯度因此为零；weight decay 造成参数变化也不等于学到了材料响应。
实际审计验证 9 个网络相关数据梯度为零，recAs 外推误差明显增大。

反事实把 recAs 编码改成 recA 会改变预测，但这只是诊断，不是合法修复。
正确部署动作是未知类别拒绝或进入明确的迁移学习分支。未来可加入有辨识力的材料物性输入与覆盖数据，
但不能在当前没有证据时声称已经解决材料泛化。

第 07B 章的负结果不是首个 gate 失败就 blocked，而是诊断后确定信息支持不足，并交付可执行拒绝规则。
拒绝未知材料不证明已知材料全部可靠，仍需误差、区间和物理范围检查。

## 13.10 95% 区间无限宽，不是需要夹紧分位数的 bug

校准集 n=13，有限样本 conformal 的目标秩为 ceil((n+1)×coverage)。
90% 时秩为 13，可以取最大校准分数；95% 时为 14，已经超出 13 个样本。
正确处理是有限区间不可得，以显式 unbounded/null 记录，而不是把秩偷偷夹到 13。

后者会给出好看的有限区间，却改变所声称覆盖水平的方法。
当前经验覆盖也不构成 OOD 的自动保证；材料类别规则本身就能识别未见类别时，不要夸大 ensemble 检测增益。

## 13.11 学习模型没有胜出，怎么继续

先检查任务公平性：相同输入权限、数据分组、输出数、训练预算、归一化和评估网格。
然后检查偏差/方差、数据覆盖、结构是否适合当前样本数。
例如 37 条标量训练数据下，某树模型默认叶子至少 20 条会无法有效分裂；修复弱基线配置是公平性要求。

反过来，历史第三循环神经边界模型比 affine 基线误差大，这是值得保留的能力结果。
可以提出多步训练、物理读出或更完整状态等后续实验，但不得在当前测试反复调参后还叫独立确认。
在学习任务中，“能解释哪里没学好并设计下一步检验”本身是交付的一部分。

## 13.12 零 Pareto 改进与工程安全未知

本项目候选下置信界的悲观超体积增益均为零，程序按预先声明的次级排序选出三个归档候选。
这不等于它已经保证性能提升，也不应该藏掉零值。
实际标签回查可以计算观测超体积变化，但仍是已归档数值结果，不是新实验。

应力/挠度可从原始输出检查，但若没有正式工程阈值，训练集最大值只能当描述性参考。
把“没有查到阈值”改成“都通过安全约束”会制造没有依据的安全结论。
第 11 章保留 engineering safety unknown；本报告不通过放宽阈值来消除这个状态。

## 13.13 长任务的执行与证据纪律

真正的长程序只启动一次，在同一前台进程/session 等待自然退出。
工具返回 session_id 不代表失败，不是重新启动的许可；也不需要清除 Goal。
不要创建 timer、watchdog、后台 job 或重复启动来表示等待。
如果进程非零退出，先诊断；若模型性能差但运行正常，按上面的能力分析处理，而不是自动重试。

记录一次开始标识和真实终态；原始日志、失败 JSON、旧源码摘要和修复后的新目录共同形成证据。
不要删除旧失败目录，不用 reset/checkout 覆盖共享工作树，不用“全部重新生成”代替具体定位。

## 13.14 故障记录模板与验收题

你自己的每次实验至少写下：任务定义、输入权限、错误或坏指标、最小复现、原因假设、
证明/反证、具体改动、回归测试、新结果、仍未证明的内容。

验收题 A：模型预测与标签 shape 都“看起来差不多”，loss 一直不为零。先检查广播，
再检查单位/列顺序，而不是先增加网络层数。提交能失败再通过的小测试。

验收题 B：故意把模型的初态改成未来阶段首帧，写一个不依赖该帧具体数值的权限测试。
正确答案应使用 API 限制或注入未来数据扰动，而不只是比较这批数据上初态差异很小。

验收题 C：某个新损失降低了能量残差却增加循环跳变。你应报告多个指标和相同种子对照，
解释多目标优化的取舍；不能用加权总损失下降代替各项物理正确。

掌握标准：你能把“实现错误、假设不足、数据缺失、模型能力不足”区分开，
为每一类提出一个有判别力的下一步检查，并知道什么时候应修程序、补任务定义或诚实保留未知。
