# 第 9 章：模型说“不确定”时，究竟是什么意思

本章对应 `learning_ensemble.py`，实际结果为 `wp6-uq-r1`，审计为 `wp6-uq-active-audit-r1`。
目标不是给预测加一个漂亮的阴影，而是回答：模型的分歧是否提示误差？区间是否校准？
遇到未见材料能否报警？报警与真正的物理失效是不是一回事？

## 9.1 点预测、分歧和概率是三个层次

普通回归网络输出一个数。例如预测 COP 为 1.7，这只是点估计，不能自动解释为准确到几位小数。
本章训练 5 个独立初始化、结构相同的网络，每个给出自己的预测。
这样得到的预测差异是模型分歧指标。Deep ensemble 是一种常用的不确定性估计路线，
但它不是自动得到的精确贝叶斯后验。[Deep ensembles 方法入口](https://arxiv.org/abs/1612.01474)

对于一个输入、第 j 个目标，有

\[
\bar y_j=\frac1M\sum_{m=1}^M\hat y_{mj},\qquad
s_j=\sqrt{\frac1{M-1}\sum_m(\hat y_{mj}-\bar y_j)^2},\quad M=5.
\]

实现使用样本标准差 `ddof=1`。这里没有 bootstrap 重采样：成员看到相同训练样本，
区别是随机初始化。也不是先训练一个网络再复制五份权重。

认知不确定性通常指模型/参数知识不足，偶然不确定性通常指数据生成中的随机性。
我们的数值案例每工况只有一次观测，没有足够重复噪声观测，不能独立辨识两者。
因此实际产物只报告 ensemble 分歧指标，`aleatoric_decomposition_verified=false`。
不能把网络间标准差直接贴上“完整误差条”或“已分解物理噪声”的标签。

## 9.2 本次模型和数据可见性

沿用 37/13/13 物理工况划分。训练集拟合模型和标准化器，校准集只计算区间尺度，测试集评估。
这份测试集以前已经看过 WP2–WP4 分数，所以新结果是开发性比较，不叫新的独立确认。

输入 7 维：5 个几何/运行数值量，加两列材料 one-hot。
输出 6 维：冷量、泵功、COP、SCP、温差，加 `Wtotal_for_COP_J`。
最后一个辅助输出为后续检查 `Qcool = COP × Wtotal` 提供条件。
注意这个等式只是标签代数一致性，不是独立系统能量守恒。当前归档 Wtotal 等于加载功加回收功量
再加泵功，不是理想净回收输入；本章校准覆盖的是这个既定标签。详见[能量读出审计](<07A1_温度场到能量的读出契约.md>)。
此前 WP2 单网络只有 5 个输出，不能把两次性能差异全部归因于 ensemble。
本章更公平的内部对照是同一个 6 输出结构下的各成员与成员平均。

各成员为 `7→32→32→6` SiLU，float64，AdamW 300 轮，学习率 0.002，
weight decay 0.0001，梯度裁剪范数 10。第 m 个成员种子为 `20260910+1009*m`。
标准化器只拟合一次训练集并由成员共用；保存权重、scaler、训练 ID 和全部训练曲线。

| 数组 | 形状 | 说明 |
|---|---|---|
| `x_train` | `[37,7]` | 原始输入，再按训练均值/尺度标准化 |
| `y_train` | `[37,6]` | 目标也按训练集标准化 |
| `member_predictions` | `[5,63,6]` | 已反标准化到原始量纲 |
| ensemble 均值/标准差 | `[63,6]` | 沿成员轴计算，不沿案例轴 |
| 校准/测试区间 | `[13,6]` | 每个工况、每个目标各有宽度 |

常见错误：沿错误的轴计算标准差，得到“不同工况之间的差异”而不是“同一工况的模型分歧”。

## 9.3 真实点预测与误差—不确定性关系

| 目标 | Ensemble 测试 RMSE | 绝对误差与分歧的 Spearman 相关 |
|---|---:|---:|
| 冷量 / J | 0.23257 | 0.2582 |
| 泵功 / J | 0.00003549 | 0.2857 |
| COP | 0.02616 | 0.1978 |
| SCP / W·kg⁻¹ | 11.47994 | 0.4890 |
| 温差 / K | 0.03309 | 0.4670 |
| COP 分母功 / J | 0.13257 | 0.4121 |

Spearman 相关比较排序，不要求线性关系。数值仅显示有限的正相关，不是“高不确定必然高误差”。
这里样本只有 13 个，不能把这些相关系数解释成稳定总体规律。
冷量的最好单成员 RMSE 约 0.16264 J，小于 ensemble 平均的 0.23257 J。
但“事后看测试分数挑最好成员”会泄漏评估信息，不能作为部署选择方法。
这也说明 ensemble 并不保证每次胜过所有成员。

## 9.4 为什么要校准，而不是直接取均值 ± 两倍标准差

五个网络不是五个独立真实测量，输出也未保证服从正态分布。
本例以 ensemble 标准差为区间形状，再用独立校准数据决定总体乘数。
用到的是 split conformal 的次序统计量思想；其覆盖解释有交换性等前提，
不能将选取的数值工况自动视为任意真实世界总体样本。[Conformal 方法入口](https://arxiv.org/abs/2107.07511)

先令 \(d_{ij}=\max(s_{ij},0.01S_j)\)，其中 \(S_j\) 为训练集目标尺度。
这个事前固定的下限避免成员碰巧一致时除以零，不是观测噪声估计。
对每个校准工况计算跨六目标的最坏标准化误差：

\[
r_i=\max_j\frac{|y_{ij}-\bar y_{ij}|}{d_{ij}}.
\]

在 n=13 个分数中选第 \(k=\lceil(n+1)c\rceil\) 小的分数 q，
给新工况输出 \([\bar y_j-q d_j,\bar y_j+q d_j]\)。
取最大值是为了构造“该工况六个目标同时覆盖”的区间，而不是六个互不相关的逐目标承诺。

本次 c=0.9 时，k=13，q=5.222639。13 个测试工况均同时覆盖；
COP 平均区间全宽为 0.202973，冷量为 1.678703 J。
不能只报覆盖率 100% 而隐藏宽度；无限宽区间也能覆盖所有数据。

算术练习（不是某个真实案例）：如果某工况 COP 均值 1.7、用于区间的尺度 0.020，
则半宽为 `5.222639×0.020≈0.10445`，区间约 `[1.59555,1.80445]`。
这里校准乘数明显大于正态分布常见的 1.645/1.96，更说明原始网络分歧不等于现成可信区间。

## 9.5 13 例为什么不能给出有限的 95% 区间

当 c=0.95 时，\(k=\lceil14\times0.95\rceil=14\)，
但手里只有 13 个校准分数。正确处理是要求无界区间，不是偷偷把 k 截成 13。
实际 JSON 返回 `unbounded_interval_required`、`finite_interval_available=false`。

要使这条有限样本公式能取到有限 95% 分位数，至少需要 19 个校准样本：
\(\lceil20\times0.95\rceil=19\)。这只是“可以算有限次序统计量”的最少数量，
绝不是“19 个样本足以证明总体安全”的结论。
本次没有为了得到更漂亮的覆盖承诺重新切数据或补跑仿真。

## 9.6 材料 OOD：完美 AUC 也可能没那么神奇

另外训练一个仅见 recA 的 ensemble：43 个 recA 工况训练，13 个 recA 工况作域内测试，
7 个 recAs 工况作材料外推。检测分数是按目标训练尺度归一化后的平均成员标准差。
检测 AUROC 为 1，但简单规则“材料是否未在训练中出现”也为 1。
因此这不证明 ensemble 比已知类别规则提供了更强的 OOD 检测能力。

架构也解释了为什么要谨慎：只训练 recA 时，材料 one-hot 列经中心化后在训练中恒为零。
相关输入权重没有这类数据变化提供的学习信号。换成 recAs 后，非零材料输入触发不同成员的
不同权重，很容易产生分歧。这不等价于网络学会了所有外推物理。

真实外推误差仍大：这个专用模型的域内/recAs 冷量 RMSE 约 0.4028/3.4841 J，
COP 约 0.02951/0.41108，SCP 约 3.09/186.39 W/kg。
能报警与能准确预测是不同能力；recAs 工况本身仍是物理有效数据，OOD 标签不是故障标签。

## 9.7 拒绝预测与风险—覆盖率

审计按不确定性从低到高排列 13 个测试工况，逐步增加保留数量，计算保留集的标准化均方误差。
排序只用不确定性，不允许用真实误差先挑简单案例。
保留 3/13 时该诊断误差约 0.000939，全保留时约 0.003821；中途并非严格单调。
这展示了“拒绝部分输入以降低接受集风险”的概念，也展示了它的样本波动。
不能把保留三个工况的良好误差当作一个已验证的部署安全策略。

## 9.8 复现与自测

```powershell
python -m unittest SciML.tests.test_learning_ensemble -q
python -u -m SciML.models.v12.learning_ensemble --dataset-root SciML/datasets/v12-learning-existing63-20260910 --original-protocol SciML/results/learning-existing63-20260910-r1/protocol.json --output-root SciML/results/my-uq-run
```

输出目录必须是新的。先查看 `protocol.json` 与 `uq_report.json`，再看预测数组，
不要只看 `summary.json` 的状态。`LearningEnsemble.load` 重载后应重现每个成员的预测。

练习 1：给出 `[M,N,K]` 数组，分别解释对三个轴求方差意味着什么。
答案：成员不确定性沿 M；工况差异沿 N；不同量纲目标之间不能不经尺度处理直接混算 K。

练习 2：手算 n=13 下 90% 与 95% 次序统计量。
答案：13 与 14，后者不存在；对应测试 `test_95_percent_interval_cannot_be_finite_with_13_calibration_cases`。

练习 3：为什么在全数据集（包括测试集）上拟合标准化器会污染测试？
答案：测试分布参与了模型使用的尺度，改变了模型本应事先固定的输入处理规则。
本例还检查了 scaler 的训练均值与真实训练集一致。

练习 4：OOD 检测 AUROC=1 能否替代跨材料预测误差？
答案：不能。检查域内/域外误差与简单类别规则，再分别陈述检测能力和预测能力。

进阶任务：在新的开发协议里比较不同成员数、不同训练种子、bootstrap 与不 bootstrap，
同时记录点误差、区间宽度、覆盖与成本。不能只按已看过的测试分数挑成员数后宣称独立验证。
掌握标准：能从保存的 `[5,63,6]` 数组独立重建均值、分歧、校准区间与风险—覆盖率，而非仅调用封装。
