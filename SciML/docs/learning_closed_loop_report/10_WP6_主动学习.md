# 第 10 章：主动学习——让模型决定下一例最值得看什么

对应代码 `SciML/active_learning/learning_pool_loop.py`，结果 `wp6-active-r1`。
本章完成了真实选择、揭示标签、重新训练和评估，但使用的是**归档标签揭示**，不是新算高保真案例。
它的价值是让你掌握完整闭环和公平实验，而不是声称已经节省了某个未来仿真活动的成本。

## 10.1 把“已有全部数据”变成一个可检查的学习实验

我们作为实验编写者有完整文件，但算法选择下一批案例时不应读取那些尚未揭示的目标。
`ArchivedLabelOracle` 只接受允许查询的训练候选池 ID，记录每次查询，拒绝重复或池外 ID。
测试与校准工况根本不进入这个池。选择函数的输入没有隐藏标签：

```text
已揭示输入/标签 -> 训练 ensemble -> 预测未揭示池
                                     |
                           只看预测和已揭示信息打分
                                     |
                         先保存选样决定 -> oracle 揭示
                                     |
                            合并新标签 -> 重新训练
```

这是 API 层的实验隔离，不是能防止 Python 内省或恶意读文件的安全沙箱。
真正要审计的是算法数据路径：哪些数值进入训练、打分、停止规则和最终评价。

池来自原训练划分，共 37 个工况。固定测试集仍为 13 个；13 个校准工况完全不查询。
每次实验先按输入/ID 哈希选 12 例，并确保已有材料组都出现在初始设计中。
之后两轮各选 5 例，所以标签预算为 12→17→22，最终还有 15 个候选标签未揭示。

## 10.2 怎样才算公平比较

三种策略为随机、仅分歧、复合策略，每种运行种子 701/702/703。
对于相同种子，初始 12 例完全相同；每轮成员数、网络结构、训练轮数、测试集均相同。
模型使用 3 个成员，每个 200 轮，结构与第 9 章相同。
本章预算是学习实验的预算，不直接与前章 5 成员/300 轮的模型归因比较。

每种策略运行 3 次初始/更新拟合，总共 9 组实验、27 次 ensemble 拟合。
实际内部计时约 33.47 秒，没有启动 MATLAB。
审计又从当时已揭示的标签独立重训每个中间模型，逐个重放了 18 次选样决定。

不能用以下做法“证明”主动学习更好：给它更多标签、只报告最好种子、让随机策略少训练几轮，
或根据测试误差停止/更改打分权重。本实现固定两轮，无测试驱动选择和停止。

## 10.3 策略一：随机采样不是稻草人

随机策略用固定种子对剩余候选打乱，取前 5 例。
随机采样能扩展覆盖，且不会完全信任小样本模型的不确定性排序，因此是必要的强对照。
主动学习若输给它，不等于代码必然有错，但需要检查分歧质量、批量冗余、目标冲突和样本波动。

## 10.4 策略二：只看网络分歧

对候选 x，计算六目标标准差按当前训练目标尺度归一化后的平均值：

\[
U(x)=\frac16\sum_j s_j(x)/S_j.
\]

尺度只来自已揭示训练集。否则不同量纲下 SCP 的数值可能压倒 COP、泵功等目标。
按 U 从高到低选 5 例；分数相同时按 case ID 排序，保证可复现。
高分只表示成员分歧大，不保证该例对所有目标、所有测试工况都最有帮助。

## 10.5 策略三：复合选样

本学习版计算三个成分，然后各自转换为候选池内的百分位排序，再等权平均。
这样处理不同分数尺度，权重事前固定，不按测试结果调整。

第一项是上述 U。第二项为标量输出之间的代数一致性：

\[
R(x)=|\widehat Q_{cool}-\widehat{COP}\,\widehat W_{total}|/S_Q.
\]

它利用项目定义中的性能恒等式，但**不是**整个系统的能量残差，更不是 PDE 残差。
仅此恒等式成立不能证明 SMA/HTF 内部能量正确；报告和代码都明确使用
`performance_identity_residual` 这个名称。

第三项是乐观的 COP/SCP 超体积改进。我们同时希望两者越大越好，
但通常不存在一个在所有目标上都最好的设计。
若 A 在所有目标不差于 B，且至少一个目标更好，称 A 支配 B；不被其他点支配的集合就是 Pareto 前沿。

在二维最大化中，用一个比已知前沿差的参考点，计算前沿与参考点之间矩形并集的面积，称为超体积。
例：参考点 `(0,0)`，已有 `(1,3)` 和 `(2,2)`，面积为 `1×3+(2−1)×2=5`；
加入 `(3,1)` 后变成 6，加入被支配的 `(1,1)` 不增加面积。
这两个事实有对应单元测试，能防止把最大化和最小化方向写反。

候选的乐观目标采用均值加一个成员标准差，再计算相对已揭示前沿的超体积增量。
前沿、目标均值/尺度、参考点都只用已揭示目标构造。
这是一种事前固定的教学启发式，不是精确贝叶斯期望超体积改进，也没有证明全局最优。

具体实现中，一个成分的 n 个分数先做升序排名；并列值取平均名次，
再按 `(rank−0.5)/n` 归一化。最终分数是三个百分位的平均值。
例如分数 `[2,2,8]` 的名次为 `[1.5,1.5,3]`，对应 `[1/3,1/3,5/6]`。
所以这里的“百分位”不是简单除以最大值，也不是把并列样本按 ID 强行排成不同分数；
ID 只在最终选样分数相等时用于打破平局。
百分位会丢失原始幅度信息；按最高分直接取一批也未额外考虑点之间的多样性，
这些都是可进一步研究的设计选择，不应该从函数封装中消失。

## 10.6 选择日志如何证明没有偷看标签

每轮都在 oracle 查询前写入 `round_0_prequery.json` 或 `round_1_prequery.json`，包含：

- 当前训练 ID 和预算；
- 未揭示候选 ID；
- 三种分数组件及复合分数；
- 已决定的 5 个 ID；
- 当轮测试指标（只用于日志，不进入打分）。

随后才允许 oracle 返回选中标签，合并训练数据。
结束后还有 oracle 查询账本、最终网络、各轮测试预测和每目标误差。
独立审计不只相信“没有泄漏”这个布尔值，而是从当时可见的训练标签重拟合，
重新计算候选分数、重放决定，并检查与查询前日志、最终预测及预算一致。
9 组实验的两轮决定全部重放成功。

为什么测试指标可以保存在日志里？因为它属于实验评估器，不传给选择函数。
但是人如果看到这些指标后改变权重/策略，下一次就属于新的开发性实验，不能声称原测试仍未触碰。

## 10.7 实际学习曲线：没有全面赢家

22 例标签预算下，以下是三个种子的平均测试 RMSE：

| 目标 | 随机 | 仅分歧 | 复合 |
|---|---:|---:|---:|
| 冷量 / J | 0.20920 | 0.32984 | 0.27804 |
| 泵功 / J | 0.00006609 | 0.00004373 | 0.00005851 |
| COP | 0.04583 | 0.05201 | 0.03751 |
| SCP / W·kg⁻¹ | 10.3702 | 9.7297 | 8.0451 |
| 温差 / K | 0.034805 | 0.029770 | 0.034800 |
| 分母功 / J | 0.17716 | 0.18536 | 0.19224 |

随机策略的冷量更好，复合策略的 COP/SCP 更好，仅分歧的泵功/温差更好。
温差里随机与复合几乎一样，不能夸大最后几位小数的差别。
初始 12 例时，各策略对同一种子的预测逐字节相同，证明确实从相同起点出发。

![同标签预算的学习曲线；阴影为三个种子的一个标准差，不是置信区间](<../../results/learning-closed-loop-20260910/wp6-uq-active-audit-r1/active_learning_curves.png>)

三种策略随预算增加总体改善，但某些目标/轮次并不单调。
只有三个种子，阴影表示运行差异，不能当作显著性检验或总体置信区间。
复合策略偏向 COP/SCP 改进，与它的目标函数有关；它不是对所有输出的公平最优保证。
没有因为冷量不如随机就反复调权重，负结果作为学习结论保留。

## 10.8 怎样接入真正的昂贵求解器

算法层只需要 oracle 接口不变，但生产版本的 `reveal` 不能直接读隐藏标签。
它应提交选中工况，记录配置与源哈希，等待真实求解结束，执行物理/观测质量门，
只有有效结果进入标签；失败要记录具体类型，不能填零或从训练集静默消失。

本次没有执行这一步，因为用户明确要求不再大量增加仿真时间。
所以我们展示的是完整的选样—标签揭示—重训机制，不宣称节约了某个已执行新仿真活动的实际预算。
下一章的候选设计也必须区分模型建议、归档数值回查和全新高保真回验。

## 10.9 复现与练习

```powershell
python -m unittest SciML.tests.test_learning_pool_loop -q
python -u -m SciML.active_learning.learning_pool_loop --dataset-root SciML/datasets/v12-learning-existing63-20260910 --original-protocol SciML/results/learning-existing63-20260910-r1/protocol.json --output-root SciML/results/my-active-learning
```

练习 A：故意向 oracle 查询一个测试 ID、已揭示 ID 或重复列表。
答案：三者都应抛错，且不能改变已经揭示的合法集合。

练习 B：手算上述三点超体积，再分别加入一个支配点和被支配点。
答案：被支配点不能增加面积；增加好点不能减少面积。对应 `test_pareto_and_hypervolume_have_correct_maximization_direction`。

练习 C：在同一轮把未揭示标签换成另一套数值，但不向选择器公开。
答案：本轮选择必须不变；下一轮揭示之后模型和选择允许变化。
若本轮选择变化，说明代码意外接触了隐藏标签。

练习 D：给随机策略和主动策略相同初始 ID、预算和网络种子，比较第一轮训练前的测试预测。
答案：必须一致。本项目审计实际检查了这个条件，而不是只比较工况数量。

进阶任务：增加输入空间多样性约束或每轮只选一个点，研究批量冗余。
先写新的实验协议和预算，再看结果；与同预算随机策略比较所有种子和目标。
掌握标准：能不依赖报告结论，从查询账本和预测 NPZ 自行重建预算、学习曲线、
Pareto 前沿，并指出原方案在何种目标上不优于随机采样。
