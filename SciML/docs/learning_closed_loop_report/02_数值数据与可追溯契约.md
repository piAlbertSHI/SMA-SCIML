# 第 2 章：数值数据从哪里来，怎样证明没有读错

## 2.1 为什么第一步不是打开 PyTorch

一个训练过程可以完全没有软件报错，却一直在学习错误含义的数据。
例如把固体温度当流体温度，把真实未来温度当初始输入，或者把被修正的储能当独立测量。
这些错误不靠降低学习率修复。本章先建立“来源—含义—用途”的数据契约。

契约不是一份写完就算的说明。它必须对应可执行检查：字段名、shape、单位、状态所属阶段、
初末时刻、允许缺失项、原始来源和版本都能逐一核对。本次新增检查对 63 个工况的 756 组
核心温度/机械数组做了原始 MAT 到 HDF5 的精确比较，全部一致；这证明这部分导出没有改值，
不等于独立证明原求解器物理正确。

## 2.2 整条链中每个程序负责什么

```text
工况/求解选项 JSON
  → Run_SCIML_V11_Pilot.m：组织既有工况运行
  → Run_GlobalXi_Simulink_Cycles.m：四阶段与循环状态传递
      → GlobalXi_TimeStep_Core.m：机械/相变/径向温度求解
      → Run_Simulink_Exchange_Hook.m：换热后端与观测/能量接口
  → Export_SCIML_V11_Case.m：固定形状的 case_artifact
  → build_dataset_v11_pilot.py：索引、HDF5、质量/来源报告
  → 学习任务检查、工况切分、训练和独立审计
```

箭头表示信息依赖，不意味着本学习阶段又执行了前面的昂贵物理程序。
我们使用已经存在的归档；执行 Python 数据读取和训练不会自动重跑 MATLAB。

原始每例的关键文件为 `sciml_case_request.json` 与 `sciml_case_v11.mat`。
前者记录工况、求解选项和实施摘要；后者是 MATLAB v7 文件，内部变量名为 `case_artifact`，
可以由 `scipy.io.loadmat(..., simplify_cells=True)` 直接读取。
不要把这个 v7 MAT 文件当作训练输出的 HDF5 文件用 h5py 打开。

## 2.3 数据目录里的八个文件

主数据目录是 `SciML/datasets/v12-learning-existing63-20260910`。

| 文件 | 用途 | 使用注意 |
|---|---|---|
| case_index.parquet / case_index.csv | 一行一个工况，参数、指标、资格、原始路径 | 教学程序优先读 Parquet，避免布尔/数值被当文本 |
| cycle_index.parquet / cycle_index.csv | 一行一个真实导出的循环 | 当前主数据每例 1 行；历史可多行 |
| fields.h5 | 大体积时间/空间数组与侧状态、能量标量 | 文件内路径不等于磁盘目录 |
| quality_report.json | 字段、有效性、矩阵覆盖等统计 | “单例有效”和“完整矩阵”分别判断 |
| provenance.json | 输入目录、构建器和配置摘要、构建时 commit | commit 不包含未提交工作树全部内容 |
| artifact_manifest.json | 数据集文件摘要清单 | 先验摘要可信时才能检测后续内容变化 |

CSV 和 Parquet 是同类索引的不同存储形式，不要把两份都拼接后将样本数算两遍。
HDF5 中既有兼容旧读取器的阶段路径，也有明确循环的 `cycles/cycle_001` 路径；
它们不是两条独立轨迹。本报告使用明确循环路径。

## 2.4 标识符、路径与一个真实例子

首个检查工况是
`paper220_reca_001_r42_t210_p0823_v1000_t2p4_1c`。
名称可以帮助人识别，但程序必须读取结构化参数，不能仅靠拆名字获得精确物理量。
同一条件还具有 condition_id，用于把同物理条件的相关样本放在同一集合。
case_id 标识归档实例，cycle/sample_id 标识循环或派生任务样本。

这个工况的内部组路径是 `/cases/fd6ef7b12f3783a63e4d`，它是 case_id 摘要的短前缀，
不是说明物理条件的标签。不要根据字典遍历位置把另一个工况的参数配过来，必须显式按 ID/索引关联。

真实原文件位于
sciml_case_v11.mat（原工作站归档，未随精简分发打包）。
这条绝对路径用于本工作站定位；迁移到另一机器时必须重新绑定数据位置，不能假装原 C 盘路径仍有效。

## 2.5 每个数组必须有 owner

owner 指哪个物理对象、哪个时刻、哪个子求解器负责给这个状态赋值。
例如卸载首帧的 xi 是机械重启后的相变量，不一定等于上一换热记录末尾持有的 xi。
边界模型因此使用“阶段+接口准备”的复合转移，而不是简单把相邻文件首尾拼接。

| 字段家族 | 主要归属 | 核心 shape |
|---|---|---|
| u_m_t、w_m_t、T_K_t、xi_t | 加载/卸载的径向机械与热状态 | 每字段 50×51 |
| sma_strip_T_K_t | 换热时固体方向性条带温度 | 50×101 |
| htf_internal_T_K_t | 换热时内部流体温度 | 50×101 |
| htf_T_in_t_K、htf_T_out_t_K | 指定流体端口观测 | 每字段 50 |
| mass_flow_t_kgps、pressure_pi_command_MPa_t | 实际流量与压力控制观测 | 每字段 50 |
| side_state | 热/冷端、buffer、路径等初末状态 | 各字段标量 |
| energy | 记录口径下的热量与残差 | 各字段标量 |

50 个时间点是导出观察网格，不是说明底层求解器只前进了 50 步。
51 点径向轴和 101 点固体条带轴不同，HTF 内部轴又不同；相同长度不代表可相减或作为同一积分坐标。
第 07A1 章还实际发现内部流体端点与端口温度可差约 13 K。

本次 756 次原始值对比的计数是：每工况 2 个机械阶段×4 个字段，加 2 个换热阶段×2 个场，
即 12 组数组；63×12=756。没有把这个数量夸大成全部字段/全部物理约束的独立验证。

## 2.6 NaN、N/A 和零并不是同一个意思

NaN 可能表示字段缺失、不可观测或该阶段不活动；零则是一个具体数值状态。
例如非活动路径温度的 NaN 不能解释为 0 K。
当前学习入口只允许以下缺失：阶段 2 的 stage4_path_pipe 初末值、阶段 4 的 stage2_path_pipe 初末值。
四种字段各出现 63 次。其他活动侧状态若缺失，程序直接拒绝，不静默填充。

之后不同模型按声明契约处理非活动槽：状态模型携带上一状态，场特征读取器采用固定 293 K 编码。
这不是说物理路径真的被重新设为 293 K；它只是输入表示。先验证“非活动”资格，再编码，
顺序不能反过来。未来拓扑变化时，要重新设计掩码，而不是把所有 NaN 都换成 293。

状态所有权掩码与缺失值掩码也不同：前者约束哪一块可更新，后者说明哪一观测可缺失。
一个字段存在且有限，不代表当前阶段有权改写它。

## 2.7 三层摘要，不要只记一个 commit

1. 原始 MAT 和请求 JSON 各有 SHA-256，用于确认读取内容未改变。
2. 数据集 manifest 绑定 HDF5、索引和报告，用于确认构建产物未改变。
3. 物理/管线实现摘要分别绑定求解实现与导出观察语义，避免相同字段名却含义变了。

当前 source_content_sha256 为
`ff28bf6eee81ed41d3a12d41c20ea4370eaf6fcdfa770e3127ae1af96db18f5c`。
训练 protocol 必须与这个来源匹配。本次数据构建记录的 HEAD 是
`cfd6d0fb035b8e2b45135a44661d2cd8c65ab63d`，但工作树包含修改，所以不能仅凭 HEAD 就声称完整复现源版本。

摘要是完整性工具，不是神奇的物理验证：错误程序也有唯一摘要；摘要和对应文件同时被改写时，
若没有可信旧基准也不能自动发现。因此训练、审计和失败证据采用新目录保存，不覆盖旧版本。

## 2.8 单例有效、矩阵完整、学习可用：三个不同判断

当前 63 例都通过学习读取器要求的 run_ok、physics_ok、paper_grade_valid、观测契约、泵功、
全场可用性和来源一致性等记录检查。字段名含 paper_grade 只说明该历史记录的单例资格。

quality_report 仍记录 expected_case_count=220、expected_matrix_complete=false。
confirmation_quality_gate 的 applicable=false、passed=false；这些没有被我们改成 true。
旧完整矩阵未运行完不妨碍按用户授权做现有数据学习，但也不允许把学习结果当旧论文门禁通过。

主数据集全为有效样本，意味着这里不能训练有正负两类证据的失败分类器。不能仅因为训练器输出
100% 分类准确率就宣称能识别无效工况。旧失败记录应单独保留；未来纳入分类任务需检查版本、
失败类型、数据可用性和抽样偏差。

## 2.9 本项目已经暴露的三个数据风险

第一，旧状态初始化曾读取未来阶段 4 的 HTF 初场，修复方式是从请求声明构建初态并重新训练，
不是只换测试输入再保留原模型解释。详细比较见第 05 章。

第二，51 点径向温度镜像丢失方向性奇分量，导致阶段 4 入口不完整；当前场连接使用自身预测的
方向记忆，而不是从真实未来场补齐。见第 06、07C 章。

第三，部分能量口径不能从精简导出独立证明：功分母有特殊符号约定，源码存在条件性储能残差
分配分支，而导出未保留所有调整前值与方法来源。见第 07A1 章。
这些发现说明“文件完整”与“任务解释正确”需要不同审查。

练习：为什么读取器先检查摘要，再检查 shape，再构造特征？
答案：先确定是正确版本，再确认结构与数值合法，最后才解释成学习输入；否则后续结果可能属于错数据。

练习：能否将旧历史 12 例与当前 63 例直接拼接？
答案：不能。先比较物理和管线摘要；历史多循环在本项目已明确采用单独版本任务。

练习：为什么每个目录写一个 summary.json 不足以证明已经完成？
答案：summary 可以与实际数组或代码不一致；需要检查它引用的产物、摘要、真实退出码、独立复算及任务覆盖范围。

独立任务：给新增字段建立“名称、对象、时刻、单位、shape、来源、缺失规则、训练权限”八列契约，
并写一个负测试证明交换固体/流体字段时会被拒绝。只检 shape 不能通过本题，因为两者都可能是 50×101。
