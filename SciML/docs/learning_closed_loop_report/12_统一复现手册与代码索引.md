# 第 12 章：统一复现手册、依赖关系与代码索引

## 12.1 “复现”要先说清复现哪一层

本章把分散在算法章节里的运行入口接成一条可执行路径。
你不需要重新运行 220 个物理案例，也不需要为了阅读报告把所有训练再做一遍。
但若要独立掌握算法，至少要完成一次合法数据读取、一次训练、一次权重重载和一次失败诊断。

本报告使用五种不同强度的检查：

| 层级 | 实际做什么 | 不能据此替代什么 |
|---|---|---|
| 环境/命令预检 | 导入库，核对数据与产物，调用 argparse --help | 不能证明完整训练成功 |
| 接口单元测试 | 用小数组检查 shape、梯度、分组、初态与拒绝规则 | 不能证明模型泛化性能 |
| 权重重载 | 从保存文件恢复模型并比较预测 | 不能证明训练可复现或数据未泄漏 |
| 重新训练 | 用相同观测、种子、预算重新拟合并比较 | 不自动证明任务物理定义正确 |
| 科学/教学审查 | 检查来源、对照、权限、负结果和适用边界 | 不自动证明真实设备有效或读者已熟练 |

本项目已对多个关键模块完成重载和重训；跨章节审核记录及最终版本核验见第 15 章。
不能把本章预检输出的 completed 当作整个项目完成。

## 12.4 第一次执行：先跑不训练的预检

选择一个不存在的新输出目录；下面命令只核验文件并调用模块 `--help`，不会运行训练或 MATLAB：

```powershell
python -u -m SciML.evaluation.learning_reproduction_inventory --dataset-root SciML/datasets/v12-learning-existing63-20260910 --campaign-root SciML/results/learning-closed-loop-20260910 --report-root SciML/docs/learning_closed_loop_report --output-root SciML/results/learning-closed-loop-20260910/reproduction-user-preflight1 --check-help
```

检查器在同一个前台 Python 进程内完成工作，未把报告命令文本交给 shell 执行。
`recipes.json` 给出命令、模块、参数和输入/输出路径是否存在；`experiment_integrity.json` 记录产物完整性；
`cli_help.json` 保存实际 argparse 帮助。它不会因为输入路径暂不存在就自动创建数据或重新跑上游。
某个路径尚待前一条训练生成时，按依赖顺序运行；已有输出目录意味着该条重放会主动拒绝覆盖。

第一次预检 `reproduction-inventory-r1` 检查了当时报告中的 42 条命令、27 个任务模块和 23 个实验根目录。
报告补充章节后命令数量会变化，因此最终预检应绑定最终章节摘要，不能把旧计数说成最终覆盖数。
此处“命令检查”意味着实际帮助和参数存在，不是把 42 条训练/审计又执行一次。

然后执行学习模块小测试：

```powershell
python -m unittest discover -s SciML/tests -p 'test_learning_*.py' -v
```

截至第 03 章补齐时，53 项学习测试通过；测试数量会随着新练习增加。
它只覆盖 learning 文件模式，不是整个仓库回归，更不会触发旧 MATLAB 任务。

## 12.5 单独重训一个模型的最短完整路径

初学者可先做 WP2。以下两个输出目录必须不存在：

```powershell
python -u -m SciML.models.v12.learning_scalar_benchmarks --dataset-root SciML/datasets/v12-learning-existing63-20260910 --original-protocol SciML/results/learning-existing63-20260910-r1/protocol.json --output-root SciML/results/learning-user-run1/wp2-strong-r1
python -u -m SciML.evaluation.audit_learning_scalar --dataset-root SciML/datasets/v12-learning-existing63-20260910 --benchmark-root SciML/results/learning-user-run1/wp2-strong-r1 --original-protocol SciML/results/learning-existing63-20260910-r1/protocol.json --output-root SciML/results/learning-user-run1/wp2-audit-r1
```

逐条执行。第一条退出码为 0 后，查看 summary、各模型误差、训练曲线和权重；再执行第二条独立审计。
不要只截一张成功图；记录输入数据摘要、源码摘要、种子、输出路径和退出码。
若遇到非零退出，停在该阶段诊断，不自动重复运行相同命令，也不删除旧目录让它重新开始。

这两条是自包含的“已有数据→重训→审计”配方。相比之下，下节一些历史审计刻意依赖失败版本，
不能仅生成一个新成功模型就满足它们的前提。

## 12.7 把 UQ、主动学习和设计串起来

这是学习决策链的最小复现组合。UQ 与主动学习是不同实验，主动学习不会偷用 UQ 全训练集模型的权重。
两者共享原始工况分组，但主动学习每轮只能使用自己已揭示的标签。

```powershell
python -u -m SciML.models.v12.learning_ensemble --dataset-root SciML/datasets/v12-learning-existing63-20260910 --original-protocol SciML/results/learning-existing63-20260910-r1/protocol.json --output-root SciML/results/learning-user-loop1/wp6-uq-r1
python -u -m SciML.active_learning.learning_pool_loop --dataset-root SciML/datasets/v12-learning-existing63-20260910 --original-protocol SciML/results/learning-existing63-20260910-r1/protocol.json --output-root SciML/results/learning-user-loop1/wp6-active-r1
python -u -m SciML.evaluation.audit_learning_wp6 --dataset-root SciML/datasets/v12-learning-existing63-20260910 --original-protocol SciML/results/learning-existing63-20260910-r1/protocol.json --campaign-root SciML/results/learning-user-loop1 --output-root SciML/results/learning-user-loop1/wp6-audit-r1
python -u -m SciML.active_learning.learning_design_loop --dataset-root SciML/datasets/v12-learning-existing63-20260910 --original-protocol SciML/results/learning-existing63-20260910-r1/protocol.json --active-root SciML/results/learning-user-loop1/wp6-active-r1 --output-root SciML/results/learning-user-loop1/wp6-design-r1
python -u -m SciML.evaluation.audit_learning_design --dataset-root SciML/datasets/v12-learning-existing63-20260910 --original-protocol SciML/results/learning-existing63-20260910-r1/protocol.json --design-root SciML/results/learning-user-loop1/wp6-design-r1 --output-root SciML/results/learning-user-loop1/wp6-design-audit-r1
```

这里新根目录下 UQ 和 active 的子目录名固定，因为联合审计按 `wp6-uq-r1`、`wp6-active-r1` 寻找结果。
设计阶段显式指向你刚生成的 active-root，不能仍指向旧 campaign 后声称使用了新训练。
每个阶段单独等待自然退出，检查终态 JSON；上一条失败时不继续下一条。

这套链演示“训练→校准/选样→重训→候选→归档回查”。新揭示的是已有数值标签，
不是新求解器运行；设计输出依然包含工程安全未知的边界，不应改成安全认证。

## 12.8 三类依赖历史失败证据的审计

| 审计 | 为什么需要历史文件 | 新模型重放的正确解释 |
|---|---|---|
| audit_learning_boundary | 读取 wp3-boundary-r1/r2 和旧源码快照，验证零残差尺度修复 | 新成功训练不自动重建旧失败；可以独立检查新模型，历史修复审计继续用原证据根 |
| audit_learning_wp5 | 比较局部反演 r1/r2 与制造 PINN，保留数值梯度问题证据 | 不能把新成功结果随意命名 r1 代替旧错误版本 |
| audit_learning_memory_cascade | 检查原输入组装、修复后串接及浮点失败快照 | 新串接输出目录不等于补齐所有原始基线和失败文件 |

这些审计的目的不只是“模型能跑”，还包括“我们声称修过的 bug 确有证据且旧证据未变”。
这就是第 05/06 章中某些 audit 命令仍指向原 campaign 的原因；它们审计原修复，不是自动审计
你随意命名的新训练目录。若扩展为可接受任意重放根的工具，必须同时显式传入历史失败依赖，
不能删掉历史对照就保留同一个“修复审核通过”的标题。

## 12.9 如何读取一个结果目录

通常先读 protocol，再读 summary，再定位具体数组和权重。
protocol 回答“计划使用什么数据、种子、预算、输入权限”；summary 是汇总，不能替代原始数组。
不同模型的权重封装不完全相同，使用其自己的 load 方法，不要把所有 .pt 当同一个类加载。

例如 WP4 的 `CoordinateOperator.load` 需要 field/feature 尺度和模型种类；历史边界
`HistoricalModel.load` 需要五种转移的 Ridge 系数、神经权重和残差尺度；集成模型需全部成员与归一化。
只保存 state_dict 而漏掉输入列顺序或 scaler，可能得到 shape 合法但物理意义错误的预测。

旧原型存在 pickle 文件，不能加载陌生来源的 pickle/checkpoint。本报告运行的是已核验本地自产文件；
新实现能采用 `weights_only=True` 的地方明确使用它，但这不把任意网络文件变成可信内容。

关键目录与报告章节对应：`wp2-strong-r1`→04，`wp3-boundary-r2`→05，
`wp4-*`→06，`field-energy-information-r1`/`staged-physics-r1`→07A，`ood-*`→07B，
`historical-*`→07C，`wp5-*`→08，`wp6-uq-r1`→09，`wp6-active-r1`→10，`wp6-design-r1`→11。

## 12.10 时间、种子与成本怎么记录

本项目多个 Python 小训练阶段为秒级或分钟级，不能将它们与昂贵原始物理仿真混为一谈。
不同 summary 的 elapsed_seconds 计时范围不同，有的含保存/重载，有的只覆盖模型阶段；
不要把所有字段简单相加当整项目墙钟时间，也不要把缺失计时当作 0 秒。
预检保留每个实验“有/无记录的原始耗时”，不编造统一加速比。

原始 seed 与变体预算已写入各 protocol。固定 seed 是确定性实验的一部分，不保证跨机器逐位一致。
换 BLAS、PyTorch 或并行线程时，先检查差异量级，再判断是实现改变、随机性、浮点运算顺序或真实性能变化。
不能随意放宽科学门禁来通过比较；数值等价容差与物理误差要求必须分开。

进阶练习：建立一张自己的运行日志，逐阶段记录开始/结束、退出码、版本、输入/输出摘要和是否调用新求解器。
验收：失败也有记录，缺计时标 unavailable，新种子不覆盖旧目录，所有汇总能回到具体数组。

它是复现导航和完整性预检，不是自动宣告原计划、教学报告或全部科学门禁通过的总开关。
