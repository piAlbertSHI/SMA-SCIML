# 第 5 章：WP3——状态、阶段接口与不借用未来信息的推演

## 5.1 从一次输出五个数，变成连续推进一个状态

WP2 输入一个工况，输出一次循环的性能。WP3 则要回答：现在系统处于什么
状态，在一个阶段及其接口处理结束后，会变成什么状态？我们希望把输出继续
作为下一步输入，而不是每一步都向求解器索取正确答案。

最小形式为 z_next=F(z_now,control)。这里 z 不是一个温度，而是包含位移、
温度、相变量、两条流体路径和若干热节点的向量。这个状态是建模选择，不是
“只要把所有能找到的数据拼起来就自然满足 Markov 性”。如果漏了储能状态、
滞回历史或阶段切换规则，再深的网络也不能凭空得到完整物理闭合。

本章还记录了两个真实问题：旧输入不小心包含未来信息；近零残差的缩放把
数值噪声放大成毫米级位移。它们比一个漂亮误差表更适合训练排错能力。

主要入口：

- 旧数据构建：[state_space.py](<../../models/v11/state_space.py>)。
- 输入与接口核验：[inspect_learning_state_contract.py](<../../evaluation/inspect_learning_state_contract.py>)。
- 新的阶段—接口模型：[learning_boundary_state.py](<../../models/v12/learning_boundary_state.py>)。
- 独立审计：[audit_learning_boundary.py](<../../evaluation/audit_learning_boundary.py>)。
- 单元测试：[test_learning_boundary_state.py](<../../tests/test_learning_boundary_state.py>)。

## 5.2 414 维状态如何排列

以下是 Python 的左闭右开切片。例如 0:51 表示索引 0 到 50，共 51 个数。

| 切片 | 状态 | 数量 | 单位 |
|---|---|---:|---|
| 0:51 | 径向位移 u | 51 | m |
| 51:102 | 横向挠度 w | 51 | m |
| 102:153 | SMA 径向温度 | 51 | K |
| 153:204 | 马氏体相变量 xi | 51 | 无量纲 |
| 204:305 | 阶段 2 流体路径温度 | 101 | K |
| 305:406 | 阶段 4 流体路径温度 | 101 | K |
| 406:414 | 8 个辅助热状态 | 8 | K |

8 个辅助量依次是 hot sink、cold sink、chip/cold load、hot buffer、cold buffer、
stage2 path pipe、stage4 path pipe、Simscape cold sink pipe。buffer 是求解器侧
流体容器状态，不应随意解释成额外的设备热蓄能器。

51 个径向节点与 101 个流动/条带节点不是同一坐标，不能直接按索引相减。
本章使用导出器提供的 51-node SMA 接口温度；WP4 会另外处理 101-node 场。

控制向量有 13 项：4 项阶段 one-hot、2 项材料 one-hot、R/t/P/V*/换热时长
共 5 项、当前阶段时长 1 项、循环编号 1 项。网络不使用最后的循环编号，
所以最终特征维度为 414+12=426。阶段时长从事前请求的 T_load、T_unload
或 exchange_duration_s 构建；核验确认这 63 例中它与实际导出时长完全相同。

不把循环编号作为特征，只消除了“用编号记答案”的路径，**并不能证明模型
会多循环泛化**。本章主数据每工况只有一个循环；第 07C 章另行使用一致历史版本的多循环数据，
两者不能混成同一来源或认为本章已自动验证多循环。

## 5.3 第一处问题：初始状态为什么不能从后面的阶段借来

旧 `build_transition_corpus` 初始化两个 HTF 向量时，分别读取阶段 2 和阶段 4
的首帧。阶段 2 首帧是 293 K；但阶段 4 首帧已经受此前物理过程影响。虽然
变量名字叫“initial”，它只是**该阶段**的初始值，不是**整个预测任务开始**时
已知的值。

本次对全部 63 个工况做了实际核验：

- 机械初始 u/w/xi 与声明静止状态完全一致，SMA 初温也一致。
- 阶段 2 HTF 初温、辅助初温与声明值一致。
- **63/63 的阶段 4 HTF 首帧不同于事前声明初温**，最大差值 0.0165883 K。

这不是可以忽略的字段来源细节。旧模型冻结不变，只把它的初始状态换成
事前声明值，第 1 阶段测试 SMA 温度 RMSE 就从 0.108866 K 变成 3.253811 K。
输入只改了一点点，预测却差很多，说明模型严重依赖这条未来信息路径。
这些小差异可能编码工况响应；经过标准化和 101 个重复节点后也不能仅凭
绝对温差很小就判断其影响很小。这里是输入替换的直接实验，不是靠猜测认定泄漏。

该实验保存在 `wp3-input-contract-r1`。它是旧模型的初始化敏感性诊断，
不是把旧模型改名为“已经修复”。修复必须同时改训练输入来源并重新训练。

## 5.4 第二个接口问题：连续数组不等于物理上没有跳变

旧构建器让前一段 `state_out` 直接成为下一段 `state_in`。这在数组层面保证
连续，却不自动等于求解器真正的阶段起始状态。核验发现：

| 接口 | 旧承接状态与真实下一阶段首帧的最大差值 |
|---|---:|
| 进入阶段 3 的径向位移 | 2.25750e-5 m |
| 进入阶段 3 的挠度 | 1.23877e-4 m |
| 进入阶段 3 的相变量 | 0.193589 |
| 进入阶段 4 的 hot sink / hot buffer | 0.00965094 K |
| 进入阶段 4 的 cold sink pipe 辅助量 | 0.00947466 K |

换热完成后的机械重平衡、restart 潜热及流体初始化会改变部分状态。
因此不能一边假定阶段 2 只改温度，一边把阶段 3 的机械初值当成前一段机械
末值完全未变。真实变换可以由物理接口函数执行，也可以在学习模型中明确
纳入一个复合过渡；不能隐瞒它，再把数组首尾相等称为物理连续性证明。

相应物理代码入口包括 `Run_GlobalXi_Simulink_Cycles.m` 的 restart 耦合处理，
以及 `Build_Simulink_Exchange_Params.m` 的阶段流体初始化、运行时 buffer
优先级。新实验没有修改它们，也没有放宽原求解器能量门禁。

## 5.5 新方案：预测“阶段计算＋可观测接口”的复合过渡

为了使用已有数据完成可解释的自主预测，我们重新定义五个边界 B1…B5。

| 边界 | 位置 | 数据来源及约定 |
|---|---|---|
| B1 | 加载之前 | 只用请求中的参考温度、明确的默认热初值及静止 u/w/xi |
| B2 | hold exchange 开始 | 加载末机械状态、阶段 2 起始温度与辅助状态 |
| B3 | unloading 开始 | 阶段 3 首帧机械重平衡状态、阶段 2 输出流体与辅助记录 |
| B4 | cooldown exchange 开始 | 卸载末机械量、阶段 4 起始温度与实际接口辅助状态 |
| B5 | cooldown 观测结束 | 阶段 4 输出，机械量保持 B4；尚未包含未观测的下一循环 restart |

训练时，B2/B3/B4/B5 的测量作为监督目标合法；推理时，不能再读取它们。
`autonomous(model, requests, case_ids)` 的参数里没有 `TransitionRecord`、
真实下一状态或 HDF5 句柄，内部从 B1 开始，连续预测四次。

B3 的辅助量取阶段 2 的已记录输出，是当前导出条件下的明确约定，不声称
恢复了所有未输出的内部储能变量。B5 也不是经独立验证的下一循环 B1。
因此这是“因果输入的单循环复合边界模型”，不是已经证明充分的 Markov 状态。

### 谁能在每个复合过渡中改变

| 过渡 | 允许模型更新的块 | 维度 |
|---|---|---:|
| B1→B2 | u、w、SMA温度、xi | 204 |
| B2→B3 | 上述机械/温度量＋HTF2＋8辅助量 | 313 |
| B3→B4 | 机械/温度量＋HTF4＋8辅助量 | 313 |
| B4→B5 | SMA温度＋HTF4＋8辅助量 | 160 |

阶段 2 的机械量被允许更新，是因为过渡包含下一阶段的机械重平衡，不是在
声称换热积分器本身直接求解了力学。阶段 3 允许 HTF4/辅助变化，也是因为
包含 coldflush 初始化与已观测接口传递。掩码随目标语义改变，不能拿新掩码
去改原纯阶段模型的结果并声称两者定义相同。

增量组装时未激活的通道原样保留；之后还会执行第 5.6 节的统一投影，因此若人为给入越界状态，
非活动量也可能被投影改变。当前有效案例的承接一致性已逐项检查。构建器核对真实边界与掩码一致，发生未声明的变化
就报错。缺失仅允许已确认的非活动路径辅助通道，其他缺失不能统一填 293。

## 5.6 Ridge 基线与神经残差怎样组合

每个过渡有一个 Ridge 增量模型和一个两隐藏层 SiLU 网络。共同特征经训练集
StandardScaler 处理，只有 37×4=148 个训练过渡，仍是 37 个独立训练工况。

设 m_s 为阶段掩码，d_s 是相应活动维度。模型形式为

\[
\Delta z_{s,active}=A_s\widetilde x+b_s+q_s\odot N_{\theta_s}(\widetilde x),\qquad
z_{next}=P(z+\operatorname{scatter}_{m_s}(\Delta z_{s,active})).
\]

Ridge 的 alpha=1。它先拟合目标增量，再定义神经残差
r=(z_target−z_input)_active−Ridge(x)。每个通道的 q 是训练残差的 RMS，
网络拟合 r/q。网络结构为 426→32→32→d_s；每个阶段独立参数。
四个输出层的宽度不同，不能硬把一个 160 维输出放回 313 个活动索引。

训练是 float64、AdamW lr=.002、weight_decay=10^-4、全批次 300 更新、
梯度裁剪范数 10。三颗种子同第 4 章，每阶段种子为 seed+stage×1009。
没有 nearest-neighbor fallback，没有因为末阶段难就切回预设温度曲线。
`neural=False` 是显式的 affine 消融，不是隐藏的运行时回退。

物理投影 P 当前实施：外缘 u/w 为零，轴对称中心径向位移 u(0)=0，
xi 截到 [0,1]；温度限制在 [200,400] K，位移限制在 [−0.2,0.2] m。
后两者只是宽泛的数值保护范围，不是应力、疲劳或设备安全判据。

这里没有 PDE 残差或精确能量投影；Ridge 是经验映射，不是降阶物理求解器。
“物理约束”具体指状态所有权、边界/可行域处理和接口的明确表达，不能扩大解释。

## 5.7 真实故障：把近零残差的尺度设成 1

第一次新模型运行 `wp3-boundary-r1` 的结果看似前几个阶段温度还行，但径向
位移 RMSE 达到毫米量级，末阶段温度 RMSE 达到 3.918856 K。
诊断检查点发现，中心 u[0] 和外缘 u[50] 的真实残差为零或极小，代码写成了：

```python
scale = np.where(residual_rms > 1e-10, residual_rms, 1.0)  # 失败版本
```

如果该通道单位是米，那么 fallback=1 就是一米。网络即便只剩 0.001 的
标准化输出误差，反变换后也是 0.001 m。外缘有投影归零，中心当时没有，
所以伪位移进入后续网络，经标准化后进一步影响温度和其他状态。

修复没有改变测试集、训练轮数或接受门限，而是改了两条共享实现规则：

```python
scale = np.where(residual_rms > 1e-10, residual_rms, 0.0)
normalized_residual = np.divide(residual, scale,
    out=np.zeros_like(residual), where=scale > 0)
# 推理中 correction = network_output * scale
# 近零通道自动没有神经修正，而不是放大为一个物理单位
state[u_center_index] = 0.0
```

阈值 10^-10 是这里沿用的数值零处理规则，不是通用材料容许误差；对于其他
单位体系应显式复核。此修复对零残差通道只取消神经修正，仍保留 Ridge 基线
及边界条件。不是把所有位移人为清零，也没有将神经网络整体关闭。

失败目录保留，原实现逐字节保存在
`source_snapshots/learning_boundary_state_r1.py`。新检查点 schema 为 v2，
加载器拒绝旧 v1，避免用新推理规则暗中解释旧模型。审计确认快照哈希与
第一次运行 protocol 中的实现哈希相同。

## 5.8 Teacher forcing 与 autonomous rollout 的区别

Teacher forcing：每一步喂真实记录的 B_s，只评价一步映射。它回答“如果当前
状态正确，下一步预测得怎样”。本章 `teacher_neural`/`teacher_affine` 属于此类。

自主推演：只初始化一次 B1，之后喂自己的 B2_hat、B3_hat、B4_hat。
它回答“错误进入下一步以后，整个链还能否工作”。核心循环是：

```python
state = request_initial_state(request)
predictions = []
for stage in (1, 2, 3, 4):
    controls = requested_controls(request, stage)
    state = model.predict(state, controls, stage)
    predictions.append(state.copy())
```

循环里面没有 `state = observed_record.state_in`，也没有在每阶段把温度重置成
测量首帧。保存 `.copy()` 防止后续原地更新污染已记录的历史。

误差传播的一阶直觉是 e_next≈J_F e_now+局部模型误差。一步误差很小并不保证
长链稳定；对某些通道敏感的 Jacobian 会放大输入扰动。本次零尺度 bug 就是
一个跨通道传播的真实例子，不需要靠模拟多循环来制造这个故事。

权威结果 `wp3-boundary-r2`，审计 `wp3-boundary-audit-r1`。

| 复合过渡 | 自主 affine | 自主 neural | 真实当前状态输入 neural |
|---|---:|---:|---:|
| B1→B2 | 0.264274 | 0.037417 | 0.037417 |
| B2→B3 | 0.135257 | 0.065151 | 0.062393 |
| B3→B4 | 0.273936 | 0.141076 | 0.109393 |
| B4→B5 | 0.125994 | 0.080207 | 0.077121 |

自主 neural 末阶段三颗种子分别是 0.098276、0.079294、0.063051 K。

## 5.10 审计覆盖了什么

- 63 个请求文件内容哈希与数据集一致；声明机械初态等于原始首帧。
- 252 个复合过渡的掩码没有掩盖未声明变化；重点目标与原始 HDF5 逐值一致。
- 训练 ID 仅来自 37 个训练工况；三种子重训预测及训练历史一致。
- 检查点冷加载能重放自主推演；给请求附加全 NaN 的假未来场不改变预测。
- 中心/外缘位移边界、相变量范围、非活动通道承接逐项核对。
- 全部报告 RMSE 从保存数组重算；失败源码快照、r1 结果保留且哈希核验通过。

本审计不证明完整能量守恒、完整状态可观测性、多循环稳定性、域外可靠性或
真实设备准确性。它证明的是这一个可明确描述的输入—目标—训练—推演流程。
剩余物理/多循环证据在后续章节另列，不能因为该审计通过就删除这些要求。

## 5.12 分级练习与参考答案

### A. 判别标签是否泄漏

“预测阶段 4 的温度场，输入阶段 4 首帧”与“从循环开始预测四阶段，输入阶段 4
首帧”是否同样合法？

答案：前者可以是阶段起点条件预测，后者使用了未来信息，除非该首帧由前面
预测过程产生或由可证明的事前条件确定。不要只看变量名中的 initial。

### B. 手算缩放 bug

某位移通道真实残差为零，网络输出 0.002，scale=1m。它会注入多大位移？
改为零修正策略后是多少？

答案：2 mm；零。应同时检查该通道是否存在需要严格实施的轴对称/夹持约束。
