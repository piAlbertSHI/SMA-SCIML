# 第 3 章：从文件到训练张量——每一维、每一个切分都要有含义

## 3.1 本章结束时你应该能做什么

不启动求解器，打开一个真实工况，构造 X/Y；按工况划分训练、校准、测试；
只用训练行计算归一化；解释状态和温度场数组每一维；发现时间片泄漏和未来信息泄漏。
本章对应的检查器已经在当前 63 例上运行，后面所有数字来自 `data-tutorial-r1`。

张量可以先理解成“具有明确维度和排列顺序的多维数值数组”。
NumPy 数组适合数据处理，PyTorch Tensor 还可以保存自动微分图并参与训练。
shape 相同不代表内容正确，列顺序和物理对象必须同时说明。

## 3.2 一份物理数据，三种不同的学习样本

| 任务张量 | 实际 shape | 每一行/维的意思 |
|---|---|---|
| 标量输入 X | 63×7 | 63 个工况，每个 7 个输入特征 |
| 标量标签 Y | 63×5 | 同一顺序的工况，每个 5 个性能目标 |
| 边界模型输入 | 252×426 | 63×4 个复合边界转移，每次 414 状态+12 控制特征 |
| 场模型 branch | 126×221 | 63×2 个换热阶段，每阶段 221 个条件特征 |
| 场模型标签 | 126×2×50×101 | 阶段样本、固体/流体通道、时间、空间索引 |

这里 252 条转移和 126 个场都不是新的独立物理工况。一个工况派生出的所有转移、场、时间点
必须继承该工况的集合归属。不能把两个换热阶段随机分给训练和测试。

历史多循环的 515 维状态是另一套任务接口，见 07C；不要把它硬塞进当前 414 维模型。
同样旧原型 211 维状态不是本报告主线的新边界模型，文件名中的 v11/v12 也不能替代 shape 检查。

## 3.3 标量 X 的列顺序与单位

| 列号 | 名称 | 当前范围 | 单位/编码 |
|---|---|---|---|
| 0 | radius_m | 0.032–0.042 | m |
| 1 | thickness_m | 0.000160–0.000210 | m |
| 2 | pressure_Pa | 724000–1642000 | Pa |
| 3 | flush_volume_target_ratio | 0.781–1.250 | 无量纲目标冲洗比 |
| 4 | exchange_duration_s | 2.0、2.4、2.8 | s |
| 5 | material_recA | 0 或 1 | 是否 recA |
| 6 | material_recAs | 0 或 1 | 是否 recAs |

两列材料是 one-hot 编码。不要用 recA=1、recAs=2 并假定材料之间存在数值距离关系。
未知类别应显式拒绝或进入预先定义的迁移任务，不能变成 [0,0] 后假装是已知材料。

特别注意半径与厚度在这批数据中成对变化，R/t 恒为 200（浮点表达可能有机器误差）。
因此两列标准化值几乎相同，不是读取重复列的 bug，而是实验设计相关性。
用这批数据不能识别独立改变厚度、保持半径不变时的完整响应；第 07B 的几何 OOD 是尺寸组外推，
不是独立长厚比外推。

当前全部工况材料计数为 recA 56、recAs 7，样本分布不平衡。
例如材料测试不能仅凭总体 RMSE 判断，需要按材料组和输入支持范围分别检查。

## 3.4 标签 Y 的含义与一个完整实数例子

Y 顺序固定为 `[Qcool_J,Wpump_J,COP,SCP_W_per_kg,deltaT_hot_cold_max_K]`。
单位分别为 J、J、无量纲、W/kg、K。WP6 的六输出模型额外预测 Wtotal，不能错用五输出列顺序。

首个检查工况 `paper220_reca_001_r42_t210_p0823_v1000_t2p4_1c` 为：

```text
X = [0.042, 0.000210, 823000, 1.000, 2.4, 1, 0]
Y ≈ [15.621731, 0.003066, 2.160161, 413.026633, 1.628471]
```

这些是归档标签，不是网络预测。COP 继承第 07A1 章解释的特定功分母，
Wpump 是液压功估计而非完整泵电耗。学习前必须先知道要拟合的是什么，不能只见列名就套常见物理解释。

误把压力 MPa 输入到需要 Pa 的模型，会造成 10⁶ 倍输入尺度错误。
训练归一化不是单位转换工具：训练用 Pa，推理也必须先变成 Pa，再调用保存的 scaler。

## 3.5 先划分工况，再生成派生样本

本学习主线沿用固定 condition_id 哈希划分，种子 20260910：先对唯一条件用带种子的 SHA-256 排序，
取两个约 20% 组分别作为校准和测试，余下为训练。具体键值与实现位于 `split_conditions()`。
采用哈希是为了不依赖原始文件枚举顺序，不是让切分自动具有统计代表性。

| 集合 | 工况数 | recA | recAs | 边界转移行数 | 换热场行数 |
|---|---|---|---|---|---|
| train | 37 | 31 | 6 | 148 | 74 |
| calibration | 13 | 12 | 1 | 52 | 26 |
| test | 13 | 13 | 0 | 52 | 26 |

测试集恰好没有 recAs，不能据此评价材料迁移。不要为了让这个表好看临时重切；
另设明确定义的材料留组任务更合理，具体见第 07B 章。

代码应保存 split manifest，模型报告记录训练 ID。训练、校准、测试在 case_id/condition_id 层不相交，
随后从每条状态/场样本的 condition_id 查回布尔 mask，而不是为每种任务重新随机划分。
此处 calibration 用于后续区间校准，不是随意用于早停或参数选择的验证集；更改用途需要改协议。

正确的逐行 mask 不足以证明无泄漏：下面的 train/test mask 在行层不重叠，但工况 a 被拆开了。

```python
# exercise: group_leakage
import numpy as np
from SciML.evaluation.inspect_learning_data_tutorial import grouping_counts
ids = np.array(['a', 'a', 'b'])
bad_masks = {'train': np.array([True, False, False]),
             'test': np.array([False, True, True])}
try:
    grouping_counts(ids, bad_masks)
except ValueError:
    print('correctly rejected case leakage')
else:
    raise AssertionError('the same case entered train and test')
```

预期打印 `correctly rejected case leakage`。这类错误不会被“训练 loss 下降”发现。

## 3.6 归一化必须只看训练行

对每列训练输入计算 μ 和 σ，使用标准化 x_tilde=(x-μ)/σ；输出同理。
这相当于选择合适的坐标尺度，让压力、尺寸、功和温度不会仅因量纲大小支配优化。
StandardScaler 使用总体方差约定（ddof=0），不是误差条使用的样本标准差（ddof=1）。

首个工况压力的真实计算为

\[
\tilde P=\frac{823000-947540.5405405406}{198415.69720414034}
\approx-0.62767484.
\]

首例 Qcool 的标准化为

\[
\tilde Q=\frac{15.6217313943-14.3642485768}{4.0865444386}
\approx0.30771299.
\]

归一化后首例 X 约为
`[1.258885,1.258885,-0.627675,-0.242157,0,0.439941,-0.439941]`。
换热时长 2.4 恰好等于训练均值，因此这一列为零；这不意味着其物理时长为零。

预测输出必须用训练 Y 的同一个 scaler 反变换：y_hat=σY*y_tilde_hat+μY。
不允许在单个新工况上重新 fit，也不能把测试标签用于拟合 Y 的尺度。
每个网络/任务可能有不同归一化方案；不要拿 WP2 的列均值给 WP4 的 221 维 branch 用。

`scaling_demo()` 做了一个可执行负例：复制数据，把所有非训练输入加 10⁶。
正确的训练集均值和尺度完全不变；错误地在全数据 fit 后，均值最大偏移约 412698.464。
这个加常数操作只用于展示数据访问依赖，不是物理扰动，也没有修改源数据。

```python
# exercise: scaler_permission
import numpy as np
from SciML.evaluation.inspect_learning_data_tutorial import scaling_demo
X = np.arange(28., dtype=float).reshape(7, 4)
before = X.copy()
result = scaling_demo(X, [True, True, True, False, False, False, False])
assert result['train_only_mean_unchanged_exact']
assert result['train_only_scale_unchanged_exact']
assert result['wrong_global_mean_max_change'] > 1e5
np.testing.assert_array_equal(X, before)
print('train-only scaler and original data preserved')
```

## 3.7 从读取到 Tensor 的完整最小代码

在仓库根目录进入 Python，以下代码不会训练、不会写文件，也不会启动 MATLAB。
它与正式检查器使用相同来源，但刻意展开每一步，便于你逐行理解。

```python
# exercise: scalar_tensor
from pathlib import Path
import json
import numpy as np
import pandas as pd
import torch
from sklearn.preprocessing import StandardScaler
from SciML.models.v12.run_learning_existing import validate_dataset, FEATURES
from SciML.models.v11.cycle_proxy import TARGETS

root = Path('SciML/datasets/v12-learning-existing63-20260910')
table, quality, missing = validate_dataset(root)
protocol = json.loads(Path('SciML/results/learning-existing63-20260910-r1/protocol.json').read_text())
assert quality['source_content_sha256'] == protocol['dataset_source_content_sha256']
train = table.condition_id.isin(protocol['condition_splits']['train']).to_numpy()
X = np.column_stack((table[list(FEATURES)].to_numpy(float),
                     (table.material_id == 'recA').to_numpy(float),
                     (table.material_id == 'recAs').to_numpy(float)))
Y = table[list(TARGETS)].to_numpy(float)
sx = StandardScaler().fit(X[train])
sy = StandardScaler().fit(Y[train])
tx = torch.from_numpy(sx.transform(X[train])).double()
ty = torch.from_numpy(sy.transform(Y[train])).double()
assert tuple(tx.shape) == (37, 7)
assert tuple(ty.shape) == (37, 5)
assert torch.isfinite(tx).all() and torch.isfinite(ty).all()
np.testing.assert_allclose(sy.inverse_transform(sy.transform(Y)), Y, rtol=1e-14, atol=1e-12)
print('scalar tensors: 37x7 inputs, 37x5 targets, float64')
```

`.to_numpy(float)` 把表格变数值数组；`column_stack` 按列拼接；布尔 train 选择完整训练工况。
`torch.from_numpy()` 通常与 NumPy 数组共享存储，后续若原地修改需要小心；本例只读这些数组。
`.double()` 明确使用 float64，与当前教学网络一致。模型也是 double，不能让参数与输入 dtype 不一致。
CPU 足以完成本项目小模型；本代码不把张量移动到 GPU，GPU 结果也不默认逐位等同 CPU。

## 3.8 状态模型的 414→426：不要让未来帧成为初态

当前边界向量包含 u51、w51、SMA温度51、xi51、HTF2温度101、HTF4温度101、side8，共414维。
控制构造器先给 13 维，最后一维是当前固定单循环标志；`features()` 去掉最后一维，
得到 414+12=426。12 维是阶段 one-hot4、材料 one-hot2、几何/运行5、当前阶段时长1。

每个复合转移有 state_in/state_out，监督标签通常是后态减前态或线性基线残差。
构造训练目标时读取未来 state_out 合法；自主推演接口若还读取它就不合法。
本报告主线使用 `learning_boundary_state.build_boundaries()` 和请求初态，不推荐直接复用
旧 `state_space.build_transition_corpus()` 的初态读取：旧接口曾含未来阶段 4 的 HTF 初场。
保留旧文件是为了追溯已有结果，并不意味着它是推荐新任务入口。

读取记录时还要区分“阶段物理末态”和“下一阶段准备后态”。温度、xi 或 side-state 可能经历
机械再平衡/路径准备，不能任意用上一条数组末行替代下一条首行。第 05 章逐个映射来源。

## 3.9 场模型的 221 维条件与 50×101 标签

从 HDF5 取两个换热阶段，分别构造固体和内部流体温度场。
每个阶段标签为 [2,50,101]，顺序固定为 SMA 在前、HTF 在后；只用所需字段，不把端口温度混进内部场。

branch 的布局是：

| 切片 | 长度 | 内容 |
|---|---|---|
| 0:101 | 101 | 初始 SMA 条带减去自己的均值 |
| 101:202 | 101 | 初始 HTF 场减去自己的均值 |
| 202:204 | 2 | 上述两个初始均值 |
| 204:206 | 2 | 换热阶段 one-hot |
| 206:208 | 2 | 材料 one-hot |
| 208:213 | 5 | 半径、厚度、压力、目标冲洗比、换热时长 |
| 213:221 | 8 | 初始 side-state 编码 |

均值与零均值形状分开，可以避免近常数场的每个节点被极小训练标准差放大。
这不是简单把全部初始温度减 293；物理尺度下限也按特征家族分别设定，详细实现见第 06 章。
`causal_delta_features()` 只抽取上述表示，虽然它所在旧候选文件还有历史时序先验常量，
当前坐标型 DeepONet 没有因此自动使用那些旧候选先验。

每个坐标在网络中归一化为时间 τ∈[0,1]、位置 x∈[0,1]，可再映射到 [-1,1] 送进 trunk。
训练监督为时间索引 0,2,…,48,49（26 个）和空间索引 0,2,…,100（51 个）。
不要把 `target[::2]` 当成完整时间规则，它会遗漏最后索引49。

真实入口场是单阶段条件预测的合法输入，但从整个循环开始预测时尚不可知。
把模型从“真实入口”迁移到“预测入口”需要新的状态到场连接和方向记忆，不是只改函数名为 autonomous。

## 3.10 缺失、索引、广播：最常见的三个软件陷阱

缺失：不能先 `nan_to_num` 再检查。应先按阶段确认非活动槽，再按契约编码。
当前四种非活动路径初末字段各缺 63 次，活动状态必须有限。场中的 NaN 不能作为“背景”进入均方误差。

索引：HDF5 的 `array[0]` 是该阶段第一帧，不是整个循环首次状态。
同一工况有多个组路径时，要先确认 cycle、stage 和物理对象，再取时间索引。

广播：预测 shape [N,1] 与目标 [N] 相减会广播成 [N,N]，程序可能仍能运行并下降 loss。
所以先断言 `prediction.shape == target.shape`，不能只问“有没有报错”。

```python
# exercise: broadcasting
import numpy as np
prediction = np.array([[1.], [2.], [3.]])
wrong_target = np.array([1., 2., 3.])
assert (prediction-wrong_target).shape == (3, 3)
target = wrong_target[:, None]
assert prediction.shape == target.shape
assert np.mean((prediction-target)**2) == 0
print('broadcasting trap detected')
```

## 3.11 训练和评价权限检查清单

在启动后面的模型前，逐一问：

1. 输入中的每个字段在预测时是否真的已知？“数据集中存在”不是“推理时有权限使用”。
2. 所有 scaler、POD 基底、标签尺度和校准量分别使用了哪些 ID？
3. 同工况时间片、循环、不同阶段是否被拆到多个集合？
4. 观察到测试失败后是否调整了配置？若是，新结果应标为开发/探索，而非全新确认。
5. 固定种子只控制初始化，是否还保存了列顺序、超参数、模型版本与输入含义？
6. 缺失字段是非活动、不可测、被删除拓扑，还是文件损坏？这些含义不能用统一填充值掩盖。
7. 指标是否在正确物理单位下计算？多目标 RMSE 是否分别报告？

通过这些检查再训练，比对一个错误任务做一万轮优化有价值。
